Layout

Space tokens are for gaps and padding. Widths come from three layout tokens, so a page keeps its proportions in every config. Rules are in brief-foundations/SKILL.md; this page shows the result.

Widths

Three tokens, none of them scaled by density. Anything narrower is a fraction of one of them, a percentage or a grid track.

TokenValueUse for
--page-max1180pxThe widest the page's content gets. Center it; the page background fills the rest. This page stops at it.
--measure62chA column of text or a form. Lines longer than this are tiring to read, and fields wider than this look like they want a paragraph.
--sidebar-width280pxA column beside the main content: navigation, a list of steps, filters.

A page with a sidebar

The sidebar takes --sidebar-width, the main column takes the rest, and the form inside it stops at --measure. On a narrow screen the sidebar goes on top.

--measure

Density changes space, not widths

Space tokens scale with --brief-density. A width built from them shrinks when a product is compact and grows when it's roomy, so the same page breaks differently in every config. A layout token stays put.

calc(var(--space-16) * 11)
Compact, 598px
Default, 704px
Roomy, 810px
var(--measure)
Compact, 62ch
Default, 62ch
Roomy, 62ch

Do and don't

Content and padding set heights. A page that fills the window uses min-height: 100dvh on its outermost element. The check rejects any width or height made by multiplying a space token.

Do

.page  { max-width: var(--page-max); margin: 0 auto; }
.shell { display: grid;
         grid-template-columns: var(--sidebar-width) 1fr;
         min-height: 100dvh; }
.form  { max-width: var(--measure); }
.short { max-width: calc(var(--measure) / 2); }

Don't

.page   { max-width: calc(var(--space-16) * 22); }
.column { max-width: calc(var(--space-16) * 11); }
.panel  { min-height: calc(var(--space-16) * 12); }
.form   { max-width: 560px; }
